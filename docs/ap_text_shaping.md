# AP 排版与 M55 本地绘制

ARM 应用只保留复杂文本识别和排版结果绘制。HarfBuzz 在右 AP 固件中编译，M55 通过 `rpmsgshape_run` 取得 glyph ID、cluster、advance 和 offset，继续复用本地字体度量、轮廓和位图缓存。普通文本不调用排版服务。

`thirdparty/harfbuzz` 仍由 Windows 模拟器使用，ARM 不再链接。AP 和模拟器均使用官方 `src/hb-ucd.cc` Unicode 数据，并采用默认排版特性，不再强制关闭高棉文 `blwf`。此迁移不代表已验证全部东盟语言的排版正确性。

## 字库归属

两端各自只读打开 `/romfs/system/font/font.ttf`，不共享句柄或文件偏移。M55 继续按原路径取字形；AP 从 ROMFS 的 `FIOC_XIPBASE` 取得本核 Flash 地址，HarfBuzz 的字体表 blob 直接引用这段只读数据。文件保持打开直到 HarfBuzz 对象销毁，不复制 GPOS、GSUB、cmap 等大表到 RAM。不支持 XIP 的字体路径直接返回错误。

当前字体 GPOS 为 666922 字节，cmap 为 197270 字节，逐表 malloc 不适用于 AP 剩余堆。Flash 映射消除这些表副本，但 HarfBuzz 的运行缓冲、排版输出、线程栈仍消耗 RAM。

M55 与 AP 比较文件长度、SFNT 表目录和表校验和组成的摘要。不一致返回 `-ESTALE`。这是版本一致性检查，不是完整文件内容的密码学校验。ROMFS 应在字体服务停止后更新。

## 协议与边界

协议 v2 使用 BEGIN（字体和首段文本）、APPEND（剩余文本）和 FETCH（剩余字形）。每包最多 256 字节文本或 23 个字形，AP 收齐全文后自动排版并随应答返回首批字形，最后一批返回时自动释放会话。不能对任意 UTF-8 分包分别排版。256 字节以内且不超过 23 个字形只需一次往返，24～46 个字形需两次；普通文字没有这些往返。请求 424 字节、应答 488 字节，均在 512 字节 RPMSG 缓冲扣除 16 字节头后的 496 字节载荷内。

默认每段最多 4096 字节、2048 字形，每次应答等待 2000 ms，AP 专用栈 16384 字节。超时后的应答只进入持久缓冲并按序号过滤。会话结束、错误或断开时释放缓冲；下一次 BEGIN 也会清理上次会话。M55 返回数组用系统 `free` 释放。

## 构建与验证

模拟器仍用本地 HarfBuzz，可以验证文字效果，不能证明真实 RPMSG 时延或 AP 堆峰值。真机应检查普通界面、泰文、老挝文、缅甸文、高棉文、越南文组合音标、混合方向、长段落和重复切页；结合 `[SHAPE]` 日志核对请求结果、两端堆及最大连续空闲块。

## 编译开关

OS 的 `CONFIG_RPMSG_SHAPE` 是复杂排版总开关，Kconfig 默认 `n`。当前分支的 rap/rm55 defconfig 显式设为 `y`；AP 同时启用 `RPMSG_SHAPE_SERVER`，M55 同时启用 `RPMSG_SHAPE_CLIENT`。

关闭时，在 rap、rm55 两份配置中去掉 `CONFIG_RPMSG_SHAPE=y` 或通过 menuconfig 关闭该项，并重编两核固件。子选项随依赖自动关闭。M55 保留 `RPMSG_TTF_LOCAL` 和 `rpmsgshape_run` 动态导出，但接口立即返回 `-ENOSYS`，不创建 RPMSG 排版端点，也不分配排版缓冲。应用将其作为正常的功能关闭处理，退回逐字绘制，不输出失败日志。AP 不链接 HarfBuzz、不注册排版服务。

仅关闭 AP 或仅关闭 M55 都不是配套配置；开关应两核同步。应用无需因开关变化重编或换 SDK。复杂文字在关闭状态不保证组合音标、连字正确，普通文字保持原有绘制路径。


## 排版性能缓存

OS 的 M55 排版客户端复用完全相同字体实例、UTF-8 原文和方向的 AP 排版结果。所有字体共用 24 KiB 节点预算（包含元数据、原文和字形数组，不含分配器开销及调用者输出），按最近使用顺序淘汰；关闭字体时清除对应节点。缓存分配失败仍返回已有排版结果，失败请求不入缓存。AUTO、LTR、RTL 不混用，命中返回独立系统堆数组，原有释放接口不变。

`rpmsgttf_cache_bitmap_enable(true/false)` 统一控制位图和排版缓存：首次开启一起启用，引用计数归零时一起释放；仍有其他使用者时继续保留。关闭缓存不关闭排版功能，只停止复用结果。字体关闭或变更时清理对应排版节点。两者分工为：位图缓存减少栅格化，新增缓存减少重复的跨核排版请求，不保存位图。每 64 次调用输出 `[SHAPE_CACHE] hit=... miss=... remote_ms=... max_ms=... bytes=...`；remote_ms 为该窗口实际调用耗时总和，max_ms 为单次最大值，不能把 AP 相邻完成日志的间隔当作纯 HarfBuzz 计算耗时。

2026-09-15 提供的日志包含 1007 次成功排版；8 次外部视图更新耗时中位数约 2211 ms、最大 5300 ms。此数据为优化前基线，优化后需同一文本和操作的设备日志对比；主机编译通过不代表已验证设备加速幅度。


协议 v2 需要 AP 与 M55 同步更新，不兼容旧版线协议；应用公开排版接口和字形结构不变。异常中断由延迟回收、断开或下一次 BEGIN 清理。`[SHAPE_RPC]` 记录未命中请求的 trips、total_ms、compute_ms 和结果，total_ms 包含绑定等待及跨核流程，compute_ms 为 AP 字体准备与排版函数的耗时（不含传输，不等同于纯 HarfBuzz 内部 CPU 时间）。两者均使用系统 tick 计时。

2026-09-15 协议 v2 真机日志：108 次未命中请求全部成功，其中 53 次一轮往返、55 次两轮；请求平均 38.5 ms，AP 字体准备及排版平均 35.9 ms。已输出统计窗口的缓存命中率为 99.07%。14 次外部视图更新中位数 216 ms、最大 403 ms。不同日志的操作样本并不完全一致，不能作为严格基准；仍有 5 次位图缓存 release underflow 告警，本次未调整页面开关配对逻辑。


## 混合文字与选区

保留 SheenBidi。公共整形入口先按双向视觉 run 分段，再按 Unicode Script 分段；Common/Inherited 字符随相邻脚本处理，合并后 cluster 始终指向原文 UTF-8 字节偏移。测量与绘制共用该入口，单脚本结果直接转移所有权，避免额外字形复制。

选区不再关闭整形：按原文字符索引与 cluster 区间相交判断，选择组合字符的一部分时整组高亮；先画背景再画字形。未整形的 RTL 回退使用 SheenBidi 镜像表，并保持现有输出缓冲长度约定。字体文件、字号、行高不变，普通中英文仍走原有逐字路径。
